FDE の仕事は「動くもの」だけでなく、**顧客が自走できる状態**まで責任を持つこと。各フェーズで次の成果物を残すと、引き継ぎと成果の説明がしやすくなる。数値欄は案件ごとに実測値を入れ、推測値を書かない。

## 1. 業務分析シート（要件定義）

| 項目 | 記入内容 |
| --- | --- |
| 対象業務 | 業務名・担当部署・頻度 |
| 現状の手順 | ステップごとの作業内容と所要時間（実測） |
| AI に任せる作業 | 下書き・分類・要約など |
| 人が残す判断 | 承認・確定・例外対応 |
| 入力データ | 所在・形式・機密区分 |
| 成果指標 | 何がどれだけ変われば成功か（[PoC 合意書](/references/poc-agreement)と連動） |

## 2. 評価計画（設計〜テスト）

- ゴールデンデータの件数・作成者・作成日
- 評価観点（正確性・網羅性・形式・トーン）と合格閾値
- 回帰評価の実行タイミング（プロンプト / モデル変更時）
- 詳細は[評価パターン](/patterns/evaluation)

## 3. リスク登録簿

| リスク | 影響 | 対策 | 担当 |
| --- | --- | --- | --- |
| 誤った出力が顧客に届く | | 承認フロー（[Human-in-the-loop](/patterns/human-in-the-loop)） | |
| 機密情報の外部送信 | | 区分表と匿名化（[機密入力](/patterns/confidential-inputs)） | |
| プロンプトインジェクション | | 入力の分離・権限最小化 | |
| モデル更新による挙動変化 | | 回帰評価 | |

LLM アプリ特有のリスクの網羅には [OWASP Top 10 for LLM Applications](https://genai.owasp.org/llm-top-10/) が参照しやすい。

## 4. 運用移管書（導入・保守）

- 運用担当者と問い合わせ窓口
- プロンプト・参照文書の更新手順と承認者
- 監視項目（利用量・エラー率・修正率・コスト）
- 停止・ロールバック手順
- 次の改善候補（バックログ）

## 5. 成果報告（クロージング）

- 合意した成果指標の導入前 / 後の実測値と測定方法
- 想定どおりにいかなかった点と理由
- 横展開できる業務の候補

## チェックリスト

- [ ] 全成果物に作成日・作成者・顧客側承認者が記載されている
- [ ] 数値はすべて実測値で、測定方法が書かれている
- [ ] 顧客側の担当者だけで運用を継続できる
