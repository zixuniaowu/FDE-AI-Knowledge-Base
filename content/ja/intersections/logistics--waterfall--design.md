## 現場メモ

### この交点の要点

- WMS / TMS の確定データ（追跡番号・ステータス）を入力にし、AI は文章生成と分類だけを担う
- 顧客への通知は担当者が承認してから送る（Human-in-the-loop）

### この領域特有の注意

- 配送状況の事実（日時・場所）は必ずシステム値を差し込み、AI に生成させない
- 外部 API 障害時に旧テンプレートで送れるようにする

### 成果物チェックリスト

- [ ] データフロー図
- [ ] 通知の承認フロー
- [ ] 障害時の代替手順

### よくある落とし穴

- AI に配送予定日を推測させる
- 承認なしの自動送信

## この工程で FDE がやること

1. 業務フローを「AI に任せる / 人が判断する / 外に出さない」に分ける。人の判断: 運行可否・事故対応方針・補償の判断
2. 正本は配車システム・WMS・TMS。AI の出力は下書きとして扱い、確定は運行管理者・センター管理者が正本側で行う設計にする
3. 確認画面に出す観点を 3 つ以内に絞る（全件の流し読みを防ぐ）
4. ログ（入力・出力・確認結果）の保存先と期間を決める

## この領域で特に注意すること

| 観点 | 物流・サプライチェーンでの内容 |
|---|---|
| 人に残す判断 | 運行可否・事故対応方針・補償の判断 |
| 確定する人 | 運行管理者・センター管理者 |
| 正本システム | 配車システム・WMS・TMS |
| 慎重に扱うデータ | 届け先の氏名・住所・電話番号 |
